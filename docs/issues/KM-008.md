## Summary
After approving the public Pages preview, connect the registered root domain `krunchymonkey.dev` to this public site and validate HTTPS. Do **not** touch the private app's LAN hostname.

## Context
Cloudflare is authoritative DNS. Actual private application is served at `tg.krunchymonkey.dev` via LAN-only DNS and Caddy DNS-01.

## Acceptance criteria
- [ ] Owner explicitly approves public apex DNS cutover.
- [ ] `krunchymonkey.dev` is configured as custom domain in repo Settings → Pages; Pages Actions needs no CNAME file.
- [ ] Cloudflare apex A records match GitHub's current official IP list; DNS-only initially to simplify TLS.
- [ ] Verify external HTTPS validity for `https://krunchymonkey.dev`, expected redirect policy, and project/privacy links.
- [ ] Preserve existing registrar, nameserver, email, ACME DNS challenge and all unrelated records.
- [ ] Confirm no public DNS or WAN endpoint exposes `tg.krunchymonkey.dev`; do not add port forwarding, tunnels or public Cloudflare proxy to the private app.
- [ ] Document rollback of only the apex records and Pages setting.

## Dependencies
KM-007 successful Pages preview, owner Cloudflare access, validated domain configuration.

## Technical notes
DNS changes are owner-approved. Public website availability is independent of private research application availability.

## Summary
Validate the public site deterministically, preserve design screenshots as visual baselines, and make PR review evidence easy to compare.

## Context
Existing `scripts/check_site.py` and `scripts/build_site.py`, reference screenshots under `docs/reference/`, and `.github/workflows/validate.yml` provide an initial low-dependency foundation.

## Acceptance criteria
- [ ] CI fails on broken internal links, missing images/CSS, invalid relative paths or missing page metadata.
- [ ] The deploy artifact contains only the allowlisted HTML/CSS/optimized logo/favicon, not docs, original source assets, or secret files.
- [ ] Desktop 1440px and mobile 390px screenshots are produced for visual changes, compared to approved references and attached or linked in PR.
- [ ] Explain any browser-font/antialias differences rather than making an unstable exact-pixel threshold mandatory across OSes.
- [ ] Protect against accidental sample client-data or secret token paths in public output; don't echo secrets while scanning.
- [ ] Verify both preview subpath and apex-root relative-link behavior.

## Technical notes
Prefer stdlib Python and optional local Playwright only for screenshots. Do not make the site depend on an expensive build chain.
## Definition of done
- [ ] Small reviewed PR (or documented owner-only deployment action).
- [ ] Run `python scripts/check_site.py` and `python scripts/build_site.py`; record outcomes.
- [ ] No real family-history/client information, token, credential, local secret location, or private network information is introduced.
- [ ] Update `docs/CLAUDE_HANDOFF.md` and relevant documentation if the implementation decision changes.
- [ ] Don't close until acceptance criteria have actually been verified.

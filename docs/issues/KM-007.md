## Summary
Deploy the static mockup free of charge from this repo to GitHub Pages using GitHub Actions before modifying public DNS.

## Context
Workflow: `.github/workflows/pages.yml`. Build: `scripts/build_site.py`. Public preview URL: `https://krunchymonkey.github.io/krunchymonkey-site/`.

## Acceptance criteria
- [ ] Repository Settings → Pages is set to **GitHub Actions**, not a branch conflicting with the workflow.
- [ ] Action validates links, builds allowlisted static artifact, uploads and deploys it.
- [ ] Public preview URL loads over HTTPS with correct image, CSS, links, project page and privacy-draft page.
- [ ] GitHub Actions deployment succeeds after push to main; PR validation remains separate from publishing.
- [ ] No billing requirement, secret token, backend/database, private app content or DNS change is introduced.
- [ ] Record actual Pages URL and deployment verification in issue/PR.

## Dependencies
KM-001 assets and baseline must be in the GitHub repository. Repo creation itself is an owner-authenticated CLI action.

## Technical notes
Preview first; production apex-domain DNS belongs to KM-008 and requires owner approval.
## Definition of done
- [ ] Small reviewed PR (or documented owner-only deployment action).
- [ ] Run `python scripts/check_site.py` and `python scripts/build_site.py`; record outcomes.
- [ ] No real family-history/client information, token, credential, local secret location, or private network information is introduced.
- [ ] Update `docs/CLAUDE_HANDOFF.md` and relevant documentation if the implementation decision changes.
- [ ] Don't close until acceptance criteria have actually been verified.
